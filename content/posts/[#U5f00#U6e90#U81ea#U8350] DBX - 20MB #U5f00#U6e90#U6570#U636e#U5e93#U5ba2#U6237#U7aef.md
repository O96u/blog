Navicat 好用，这没得洗。界面熟、功能全，公司电脑上几乎是标配。

但个人用、自己折腾服务器的时候，账很难算：授权要钱，安装包不小，想连 Redis 再连 MySQL，还得纠结买 Premium 还是装两个产品。正版价格看一眼就想关掉页面。

后来翻到 **DBX**：大约 **20MB**，**Apache-2.0**，一个窗口能连 **80+** 种库。装完第一感觉不是「又一个客户端」，而是——这东西怎么这么轻。


[GitHub：t8y2/dbx](https://github.com/t8y2/dbx)


![DBX 主界面](https://s.muxui.com:8015/images/2026/09/V7hMyEKFCrHl.webp)

## 先说结论

日常连库、写 SQL、看表、导一点数据，**DBX 够用，而且更轻**。你要的是企业级建模、定时任务、报表和原厂支持，**Navicat 仍然更稳**。两者可以并存，不必站队。

::callout{type="tip"}
已经有 Navicat / DBeaver 连接的话，DBX 支持直接导入，不用一个个重填。试错成本接近为零。
::

## 它到底是什么

Rust + Tauri 2 做的跨平台客户端，不内嵌 Chromium，也不绑 Java。官方文档：[https://dbxio.com](https://dbxio.com)

MySQL、PostgreSQL、SQLite、SQL Server、Oracle、Redis、MongoDB 这些日常货都在；ClickHouse、DuckDB、TiDB、OceanBase，以及达梦、人大金仓、GaussDB 也能连。一部分冷门库走 JDBC Agent，不是每种都同等深度，但「先连上」这件事，比 Navicat 拆一堆版本省心。

桌面端、Docker Web、CLI 是同一套连接。公司机器不让装客户端时，丢一行 Docker 也能在浏览器里干活。

## 为什么值得装

**真免费，不是试用倒计时。** Apache-2.0，功能不锁付费档。仓库写明不收集遥测，自动更新只去 GitHub Releases 看版本，设置里能关。

**体积对得上「随手打开」。** 大约 20MB。DBeaver 要 Java，一堆 Electron 客户端还带着整颗 Chromium。DBX 是下载、安装、连库，流程短。

**一个窗口覆盖你会碰到的库。** 业务用 MySQL、缓存看 Redis、文档翻 MongoDB，再加一两套国产库——Navicat 这边通常要 Premium。DBX 塞进同一个侧栏。

![DBX 特性与支持的数据库](https://s.muxui.com:8015/images/2026/09/rYSWTdJWhf6O.webp)

**AI 和 MCP 是写进产品里的。** 选中一张表，用自然语言生成、解释、优化 SQL，支持 Claude、OpenAI，以及 Ollama 本地模型。生成的 SQL 执行前有安全检查。Cursor、Claude Code 可以通过 MCP 直接走你已经配好的连接，不用在编辑器和客户端之间复制粘贴。

界面也更接近现在常见的编辑器，而不是传统客户端那套皮肤：


![浅色界面](https://s.muxui.com:8015/images/2026/09/vZDFvewqn7ZJ.webp)
![深色界面](https://s.muxui.com:8015/images/2026/09/JAtH3Ts40ryC.webp)

数据表格是虚拟滚动，大结果集不容易把窗口卡死；ER 图、Schema 对比、执行计划这些「打开就能看结构」的能力也有：

## 和 Navicat 到底差在哪

Navicat 是**付费、成熟、偏传统桌面**；DBX 是**免费、轻量、偏现在这套工作流**。

| | Navicat | DBX |
| --- | --- | --- |
| 许可 | 商业软件，按版本 / 订阅收费 | Apache-2.0，功能免费 |
| 体积 | 安装包通常大一个数量级 | 约 20 MB，不内嵌 Chromium |
| 数据库 | 分产品线，全开通常要 Premium | 一个客户端 80+，含不少国产库 |
| 用法 | 以桌面 GUI 为主 | 桌面 + Docker Web + CLI |
| AI | 产品内有加，偏套件功能 | 编辑器内 AI + MCP 给编程助手用 |
| 成熟度 | 十几年打磨，建模、报表、计划任务更全 | 新项目，日常查、改、导够用 |
| 迁移 | — | 可导入 Navicat / DBeaver 连接 |

不是「DBX 全面赢了」，是**你要解决的问题不一样**。个人开发者那笔 Navicat 授权，很多时候买的是习惯，不是刚需。

## 怎么装

安装包在 [Releases](https://github.com/t8y2/dbx/releases/latest)。Windows 用包管理器更省事：

::: code-group labels=[WinGet, Scoop]
```powershell
winget install t8y2.dbx
```

```powershell
scoop bucket add dbx https://github.com/t8y2/scoop-bucket
scoop install dbx
```
:::

macOS：`brew install --cask dbx`。给团队一个网页入口的话：

```bash
docker run -d --pull=always --name dbx -p 4224:4224 -v dbx-data:/app/data t8y2/dbx:latest
```

大陆可以换成 `docker.cnb.cool/dbxio.com/dbx:latest`，浏览器打开 `http://localhost:4224`。

已经在用 Cursor 的话，MCP 大致是：

```json
{
  "mcpServers": {
    "dbx": { "command": "npx", "args": ["-y", "@dbx-app/mcp-server"] }
  }
}
```

连接白名单和只读 / 读写权限在 **DBX 设置 → MCP** 里管。Windows 便携版还要加 `DBX_DATA_DIR`，指到 `DBX.exe` 旁边那个包含 `dbx.db` 的 `data` 目录。

## 别抱太高期望

::callout{type="warning"}
公司强依赖 Navicat 的建模、报表、自动化，别指望一周内无痛替换。80+ 也不等于每种库一样深——主流库最好用，冷门库有的靠 JDBC Agent，边角功能要自己试。
::

项目还年轻。GitHub 已经一万多星，迭代很快，但稳定性和文档厚度跟卖了十几年的商业软件比，仍有差距。AI 也不是开箱即用的魔法，得自己配模型端点；完全离线也可以，只用 Ollama，或者干脆关掉。

## 下手试试

还在为授权、体积、或者「再装一个只为 Redis」发愁的话，先连自己的库看一天。旧连接能导入，不行就卸，没什么沉没成本。

它解决的是：**免费、轻、一个窗口覆盖日常会碰到的库，还能把连接交给编辑器里的 AI。** Navicat 解决的是另一套问题。
